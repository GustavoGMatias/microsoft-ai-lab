# Development Principles

## 1. Problem before technology

Start with a concrete problem. Choose a Microsoft service or framework only when it is a reasonable fit.

## 2. Reproducibility

Document prerequisites, environment variables, installation, execution, and expected behavior. Provide safe example configuration files when needed.

## 3. Evaluation

Define how a project will be evaluated. For AI systems, consider correctness, groundedness, latency, cost, robustness, and failure handling where relevant.

## 4. Responsible development

Do not publish secrets or private data. Consider security, privacy, bias, accessibility, and the consequences of incorrect outputs.

## 5. Technical honesty

Clearly distinguish implemented features from planned features. Record limitations and avoid presenting a prototype as production-ready.

## 6. Learning in public

Explain important decisions and lessons learned so that another student or developer can follow the work.
